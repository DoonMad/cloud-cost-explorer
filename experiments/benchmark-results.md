Every method receives the same graph, starts, targets, node costs, and nonnegative edge weights. Each number is the median of 15 runs (larger cases use fewer repeats); one untimed warm-up is performed. All methods returned the same minimum cost and path length.

The layered cases are six-stage, complete bipartite transitions between resource choices, analogous to the app's pipeline model. Sparse cases are topologically ordered DAGs with about five outgoing edges per nonterminal vertex. The sparse cases have one start/goal; layered cases have all first/last-stage candidates as simultaneous starts/goals.

## Interpretation limits

These synthetic graphs establish behavior for this benchmark, not production performance or a universal winner. The paper's stated (O(V^2)) scan is the most direct comparison; heap Dijkstra is a stronger implementation baseline. DAG DP is (O(V+E)), and in this topologically ordered data it has no priority-queue/selection overhead. On very small graphs, constant factors and implementation details may dominate. The graph model assumes known, additive, nonnegative costs and a valid DAG; richer constraints (shared capacities, concurrent tasks, nonlinear pricing, deadlines) may require a different optimization model.
